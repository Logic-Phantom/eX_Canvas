1. **스튜디오 디자인 편집기 표시** — 컴파일러는 통과했지만 스키마 검증은 스튜디오만 한다. 생성한 `.clx` 와 `Prototyper.clx` 를 스튜디오에서 열어 확인할 것.
   (스킬의 `check_clx.py --xsd` 는 이 PC 에 Python 이 없어 돌리지 못했다.)
2. **스크린 정의** — `Prototyper.clx` 는 사업부 기본 L·M·S, 생성 CLX 는 템플릿과 같은 `EXB-FULL/DIV/PART/POP`. 대상 프로젝트의 스크린 id 가 다르면 `clxSerializer.headEl()` 을 맞출 것.
3. **타이틀 UDC 속성 전달** — 템플릿은 UDC 에 속성을 주지 않는다. 생성물은 제목이 있을 때만 `<cl:property name="title" …/>` 를 넣는다(UDC appspec 에 `title` 존재 확인함). `ctrl`(그리드 연결) 속성은 넣지 않았다.
4. **그리드 헤더 `text`** — 템플릿의 그리드 셀은 비어 있다. 생성물은 헤더 `text` 를 채운다(컴파일 통과). `columnname`/데이터셋은 만들지 않는다.
5. **Gemini 모델명** — 기본값 `gemini-2.5-flash`. 무료 등급에서 쓸 수 있는 모델·한도는 Google 정책에 따라 바뀌므로 AI Studio 에서 확인.
6. **연속 드래그** — 자동화 도구로 빠르게 3회 연속 드래그하면 3번째가 누락되는 현상이 있었다(단독 재시도는 성공). 사람 손 조작에서 재현되는지 확인.
7. **프로젝트 의존성(기존 문제)** — `udc/com/*` 가 `createCommonUtil`(eXCFrame 공통 모듈)을 요구하는데 이 프로젝트에는 그 모듈이 없다. 생성 CLX 를 이 프로젝트에서 실행하면 콘솔 오류가 난다. eXCFrame 템플릿 프로젝트에서 열 것.
